We built a triage dashboard for security across our whole fleet

2026-10-28, by Anthony “chovy” Ettinger.

How this was written: drafted with an AI assistant from my own notes, then edited by me.

back to my blog postings

I run about 300 repos on five bare metal boxes, and every one of them runs the ThreatCrush daemon. On a normal day the fleet logs around 4,000 attack events and bans about 1,800 addresses. The question was never "are we being attacked". It was "which of these things needs me today".

So threatcrush.com/dashboard is now a triage page for the whole fleet, servers and devices together.

Every box in one list. Online or offline, daemon version, and pending security updates with the CVE count per server. Today it showed nginx and libbrotli fixes (6 CVEs) on three boxes. They had already been patched by unattended-upgrades at 06:00 UTC. The dashboard was showing the previous night's check, and the small "checked 20h ago" under the number was the only hint.

Update all. The fleet sat on one version through eight releases in a day, because auto-update waits for a release to be two hours old and only checks every six hours. Now there is a button. From 0.13.59 on, daemons install the newest release on the spot and restart onto it in a few seconds.

Findings you can close. When you are signed in, every threatcrush scan, pentest and AI red-team run lands in your org. A finding is tracked across runs: new, still open, or fixed automatically when a later run of the same scope stops seeing it. Code findings are matched on the rule and the line's text, not the line number, so editing a file does not reset your notes. You triage from the web (it installs as a PWA), the desktop app, the CLI (threatcrush findings fix 3f2a9c1d) or MCP. CI can upload with an agent key, and a run that raises something new sends one alert, not two hundred.

Next: our own IPs. Our boxes were tripping our own rules. dev3 got banned by the rest of the fleet three times last week. Every server's address now goes on a known list that daemons never ban, but known does not mean trusted: if one of our addresses starts running SQL injection, that alert says it is ours. That is the choke point for a compromised box.

The CLI is free: npm i -g @profullstack/threatcrush, then threatcrush login and threatcrush scan .

Our customers block ads, so we sell them in the terminal

Almost everything we build is for developers. An AEO auditor that tells you what an LLM crawler can actually see. A dependency scanner. A CLI toolbox. An RSS directory. A pair-programming tool. The buyer is always someone with a terminal open.

That is a problem, because developers are the single hardest audience to buy. They run uBlock. They killed their Facebook years ago. A display campaign aimed at them is money handed to a filter list. So when we built our own network at crawlproof.com/ads we added a format nobody else sells: a plain text ad you can put in a terminal.

What it looks like

Here is a real one, fetched a minute ago:

$ curl -s https://crawlproof.com/api/ads/motd
+-- SPONSORED -------------------------------------------------------------+
|                                                                          |
| AI Summaries & Audio Briefings                                           |
| Read AI summaries and listen to concise audio briefings for the latest   |
| stories.                                                                 |
|                                                                          |
| Read & Listen -> https://crawlproof.com/a/7x1RTxewqUBU                   |
|                                                                          |
+------------------------------------------------- ads by crawlproof.com --+

76 columns of ASCII, text/plain, no JavaScript involved. Drop that curl in an /etc/update-motd.d script and it is your server's login banner. Put it in a CLI tool's output, a BBS login screen, an SSH welcome. It is fetched over HTTP instead of embedded in a page, which means it works everywhere a browser does not.

The part that made it possible

Ad networks count impressions in the browser, which is why a terminal format normally cannot exist. Ours counts server side, at the moment the ad is filled, on every serving path. So an impression is recorded without a single line of client script running.

The other half is the user agent rule. Every ad system on earth classifies curl and wget as bots and drops them. On this endpoint they are classified as terminals, because on this endpoint curl is not a scraper pretending to be a person. Curl is the person.

Prices

Advertisers pay $0.20 a click and nothing for impressions. Publishers earn $0.05 a click at the default bid, more if a higher bidder wins the slot, and withdraw in crypto (USDC, USDT, BTC, ETH, SOL) with a $5 minimum and a transaction hash on every payout. No traffic minimum, so a hobby box with twelve SSH logins a week earns less than a busy one but is not turned away at signup.

The catch, since there always is one

Terminals have no storage. No cookie, no localStorage, no visitor id unless the publisher passes one in the URL. That makes the audience genuinely anonymous and it also makes the impression count easy to inflate by accident. Our own dev box curls the endpoint on a timer to refresh a sponsor file, and for a while that machine talking to itself was a real chunk of the reported numbers. Tightening the duplicate window from 60 seconds to 5 took terminal impressions from 11,970 in one week to 220 in the next. Nothing changed except the counting getting honest.

Clicks are still the thing that pays, and clicks cannot be faked by a cron job.

If you ship a CLI, run a shell server, or maintain anything with a login banner, you have inventory that no ad network has ever offered to buy from you. That is the whole pitch. It is right here.

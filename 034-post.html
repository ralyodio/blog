I wanted a btop looking dashboard written in TypeScript. Nothing exotic. Bordered panels, a CPU graph that does not look like it was drawn in 1994, a process table, a meter per core, running under Bun and over SSH. Like any reasonable person I went looking for the library first.

What is actually on the shelf

blessed is still the answer everyone gives you. Almost 12,000 stars. Its most recent release on npm is 0.1.81, published on 3 September 2015, and it has 206 open issues. The repository has had commits since then. The package has not.

neo-blessed was the fork that was going to fix that. Last publish, May 2022. blessed-contrib, which is where all the charts live and which has 15,700 stars, last published in June 2022 and still resolves chalk 1.x. react-blessed is pinned to react-reconciler 0.26, which is the React 17 era, and its last commit was in 2021. That is the entire blessed family, and it is the family every "TUI in node" search result points at.

ink is the one that is genuinely, actively maintained, and it is excellent at what it does. What it does is lay out text with flexbox for command line tools. It is React: 25 direct dependencies, plus React 19, @types/react and react-devtools-core as peers. There is no framebuffer, no Braille canvas, no truecolor area graph. Spinners and boxes, done beautifully. You do not build btop in it.

terminal-kit is alive, shipped 3.1.4 in July, and carries eight dependencies. The API is the 2014 imperative one, where you drive a terminal object rather than describe a screen, and it shows.

OpenTUI is the new arrival and it is good. It also ships a native core as eight per-platform binary packages behind FFI. That is a defensible bet. It just is not the one I wanted to make, because I wanted a library I can read top to bottom, step through in a debugger, and install anywhere Node runs with nothing to compile.

So I wrote my own, with w33d and booze.

What hqtui is

5,600 lines of TypeScript and zero runtime dependencies. Not "a few small ones". The dependencies key is not in the package.json. It talks ANSI to the terminal itself.

import { createApp } from "@profullstack/hqtui";

const app = await createApp();

app.render(({ ui }) => {
  ui.panel({ title: "Hello" }, (panel) => {
    panel.text("Hello, terminal.");
  });
});

await app.start();

That is the whole ceremony. One import, and createApp() has already given you a dark theme, truecolor with automatic 256 and 16 colour fallback, the alternate screen, SGR mouse tracking, resize handling, adaptive 30fps rendering that drops to 15 over SSH, and a terminal that gets restored however the process dies, including on an uncaught exception.

What comes in the box:

  • Layout: rows, columns, grid with spans, "40%", "2fr", auto, min and max, padding, gaps, clipping, responsive breakpoints.
  • Widgets: panel, table, tree, list, log viewer, key/values, meter, gauge, donut, progress, sparkline, line, area and multi-series graph, histogram, heat bar, tabs, status bar, button, checkbox, toggle, radio, select, text input, modal, command palette, tooltip, badge, divider.
  • Graphics: a Braille canvas at 2x4 pixels per cell, plus block, half-block, quadrant and ASCII modes, gradients and software alpha blending.
  • Themes: dark by default, then dracula, nord, tokyo night, gruvbox, matrix, monochrome, high contrast and light, plus defineTheme(). NO_COLOR is respected.
  • Input: normalized keys with modifiers, mouse click, drag, scroll and move, bracketed paste, focus events, Tab traversal.

The two parts I care about

The screen is one grid of cells held in four typed arrays, so nothing is allocated per cell. Every frame is diffed against the last one and only the changed runs get written, against a model of where the terminal's pen already is, so no redundant escape sequence goes out. Changing CPU 72% to CPU 73% writes one character rather than a screen. On this box, at 160x50, which is 8,000 cells:

renderer.frame.unchanged     0.077ms      no output written
renderer.frame.1pct          0.195ms      627 bytes/frame
renderer.frame.10pct         0.286ms      2,639 bytes/frame
renderer.frame.100pct        1.523ms      8,341 bytes/frame
widgets.dashboard            0.465ms      6 panels, layout + widgets + diff

The second part is that TUIs are usually untestable, which is why so few of them are tested. There is a headless renderer, so there is no TTY in the loop:

const screen = renderToScreen(({ ui }) =>
  ui.panel({ title: "CPU" }, (p) => p.text("72%")), { width: 40, height: 6 });

expect(screen.contains("72%")).toBe(true);
expect(screen.cell(2, 0).fg).toBe(theme.title);

It also renders to text, to ANSI and to HTML, which is how the screenshots on the site get made.

Bun is the default runtime. Node 22.6 and up runs the same files with no build step, because it strips the types itself. I just ran the 91 tests on Node 24 straight off the TypeScript sources and they pass in half a second.

To see it doing something real:

bunx @profullstack/hqtui-demo          # your actual machine
bunx @profullstack/hqtui-demo --sim    # deterministic simulation

Ten screens of live host telemetry on Linux, macOS and Windows with no native dependency: sockets grouped by protocol, TCP and UDP counters with retransmit rate, HTTP traffic parsed out of nginx and apache access logs, sshd auth events, systemd units with the failures first, docker containers, kernel counters, filesystems with inode usage, logins from wtmp and the failures from btmp. None of that needs root. Running it under sudo unlocks a few more sources, and the demo tells you which ones it could not read rather than showing you a blank panel.

MIT, source at github.com/profullstack/hqtui, docs at hqtui.com. It is at 0.1.9 and the API is still moving.

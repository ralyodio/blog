nixamp 0.22 gives every live stream subtitles, and it hears your mic. Nothing leaves for a speech vendor: the ear is Whisper, run through Transformers.js on nixamp.com's own CPU, and the models are MIT licensed. Here is what shipped and what it took.

Dictate a trollbox line

Every live room on nixamp.com has a trollbox. There is now a mic button beside the box. Tap, talk, tap again. The page records with MediaRecorder, decodes it, resamples it to 16 kHz mono itself, and sends nixamp.com a small WAV. The words come back into the box, and Send is still yours, so a misheard word gets fixed before the room sees it. It works in the PWA, the desktop app and on a phone.

The button only exists where a line can be sent from, which is signed in on nixamp.com. The route behind it, POST /api/v1/speech/transcribe, answers 401 to anyone else.

Subtitles on every live

The server carrying a channel captions it while somebody is asking. Its own ffmpeg turns the stream into five-second windows, nixamp.com's ear turns each window into a line, and each line is stamped with the wall-clock moment its sound was at the live edge. The lines go out as Server-Sent Events.

The page holds every line until its own playback has reached that moment. A newcomer gets about six seconds of backlog, plus a little buffering, so a line shown the instant it arrived would be seconds ahead of the voice. Held, it lands within about a second. Close to the voice, not on it: a line is a window, not a word. Whisper takes twice as long when asked for word timestamps, and that was not worth it.

The Transcript panel is on by default when you join a live, with a switch per device. On a video channel the current line is laid over the picture too.

The same ear, three ways

nixamp transcribe clip.m4a --say https://server1.chovy.nixamp.com:4321 nixamp transcript --channel ID --follow nixamp mcp (transcribe_audio, trollbox_say, trollbox_read, transcript_read)

Two things that bit

The model library with the ONNX runtime under it is hundreds of megabytes and native per platform. The nixamp CLI tarball is pure JavaScript and runs anywhere a Node does, so the library is an optional dependency and the packer reads only the regular ones. The tarball stayed at 8 MB. The catch came at deploy: bun's auto-install at first boot reads regular dependencies only, so nixamp.com came up saying it could not hear. The container now carries a production install.

The second was ffmpeg's nobuffer flag. On a pipe it drops the packets it probed, which took the first 1.7 seconds out of every transcript and began every one mid-sentence. It is gone.

Off the cloud: sh1pt deploys to your own server now

Railway made deploying easy. Then it broke on us one too many times, and every outage was a reminder that we were renting someone else's computer to run our own code. So we are moving everything onto three boxes we own, and we built the part that made Railway worth paying for into sh1pt.

One command, your box

sh1pt ship --target deploy-ssh

That pushes the current commit to a server over ssh and puts it into service:

  • Source from any git host. GitHub, GitLab, Codeberg, or your own Gitea at

git.example.com. The box keeps a mirror and checks out the exact commit. No git remote? It rsyncs the working tree instead.

  • Releases, not overwrites. Each deploy lands in its own directory while

the old one keeps serving. A current symlink flips when the new release is healthy. If the health check fails, it flips back on its own. Rollback is a symlink and a restart, with no rebuild.

  • systemd and nginx, no containers. Your app runs as a systemd unit (bun is

installed for you), and nginx sits in front with a Let's Encrypt certificate.

  • Databases on the box. postgres: true creates a role and a database and

hands the app DATABASE_URL. redis: true does the same for Redis.

  • Secrets from the vault. The keys you list are written to a 0600 file on

the server. They travel over ssh's stdin, so they never show up in a process list.

The contract is a shell script in your repo

All the work on the server is done by one file, bin/install.sh, and it lives in your repo. It has four phases (setup, build, activate, status), it reads its settings from bin/install.conf, and running it twice changes nothing the second time. It never touches a systemd unit or an nginx site it did not write.

That means you do not need sh1pt to use it:

git clone https://codeberg.org/me/myapp && cd myapp && ./bin/install.sh

We wrote the convention down as an open spec, OpenInstall, so any tool can produce or run these scripts. To add one to a repo:

openinstall init --port 3100 --domains "myapp.com www.myapp.com" --postgres

openinstall ships in cli-tools, and the target is @profullstack/sh1pt-target-deploy-ssh on npm.

What is next

The nginx and TLS path goes live on our big database box next, then sh1pt logs, deploy-on-merge for any git host, and moving our Railway services over one at a time with sh1pt migrate.

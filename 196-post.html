TronBrowser now has its own push service

2026-09-26, by Anthony “chovy” Ettinger.

How this was written: drafted with an AI assistant from my own notes, then edited by me.

Turn on browser notifications for a site in ungoogled-chromium and you get this:

Registration failed - push service error

It is not the site's fault. Web Push works through a push service that the browser picks. Chrome uses Google's, Firefox uses Mozilla's, Safari uses Apple's. The browser keeps one connection open to it, sites send their messages there, and it wakes the browser up. ungoogled-chromium takes the Google one out and puts nothing in its place, and a web page has no way to choose a different one. So pushManager.subscribe() fails on every site.

TronBrowser runs on ungoogled-chromium, so it had the same problem. As of v3.16.0 it doesn't.

What changed

TronBrowser now runs its own push service at https://tronbrowser.dev/api/1/push, and the browser uses it by default.

  • Sites don't change anything. A page subscribes the usual way and gets an endpoint on our service. Its server sends the same standard request it sends to Google or Mozilla: an encrypted body (RFC 8291) signed with its VAPID key (RFC 8292). web-push, @profullstack/notifications and every other library that follows the spec already work.
  • We can't read your notifications. Each message is encrypted to a key that only your browser holds. The service stores the ciphertext and passes it along, and the browser decrypts it.
  • No account. A browser is identified by a random secret it generates. The service keeps which site subscribed and each message until it is delivered or expires.
  • It's a setting. Settings, Push notifications: TronBrowser (the default), any compatible service you run yourself, or off. The protocol is short and documented at tronbrowser.dev/push.

How it fits in

The engine ships as a prebuilt ungoogled-chromium, so TronBrowser can't add a push service inside Chromium. The built-in extension handles it instead. It replaces pushManager in every page before the page's own scripts run, keeps the subscription keys itself, and holds a WebSocket to the push service. When a message comes in, it decrypts it and shows the notification, and a click opens the link in the payload.

One thing works differently. An extension can't start a site's own service worker, so TronBrowser shows the notification from the payload's title, body, icon and url rather than running the site's push handler. For nearly every site that sends a notification, that is the same thing.

I tested it against the actual engine, ungoogled-chromium 152. Without the extension, subscribe() fails with the error above. With it, the site gets a working subscription, a real server's push comes back 201, and the notification appears within three seconds.

Update with tron upgrade, or grab v3.16.0 from tronbrowser.dev.

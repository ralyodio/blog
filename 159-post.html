Why I am calling this terminal experience a Live TUI

2026-09-16, by Anthony “chovy” Ettinger.

I want a name for the experience of working in a terminal app that keeps moving while individual tasks wait. My proposal is "Live TUI."

Picture one persistent workspace. A pane streams data. Another refreshes its own state. A task shows progress where that task lives, and you can keep working elsewhere in the application.

The comparison that makes sense to me is the AJAX moment for web interfaces. Partial updates let the interface respond locally. A single operation does not need to make the whole screen wait.

hqtui-demo is the example behind this idea. The details that interest me are the independent refreshes and the local loading indicators: the interface tells you what is happening while leaving the workspace usable.

The obvious challenge to the name is that the mechanics already exist. That is true. A terminal app can redraw part of its screen and run asynchronous work without adopting a new label. A name only helps if it conveys something useful about the experience.

For me, "Live TUI" sets that expectation: the workspace persists, its state stays visible, and a busy pane does not prevent you from using the rest of the app.

Does the name capture that? I'd like to hear what you would call it.

The w3bs CLI is live. It is one binary for every W3BS surface, and packages are its first app.

curl -fsSL https://w3bs.org/install.sh | sh
w3bs packages            # 65 tools, same list as w3bs.org/packages
w3bs install claude-code
w3bs update              # update everything you installed

The catalog

w3bs.org/packages lists 65 command line tools: Claude Code, Codex, Copilot CLI, Aider, OpenCode, goose, Cursor and Kiro, plus all 42 of our own, from moshcode and cli-tools to myna, sh1pt and threatcrush.

There is one rule for getting listed: a curl | sh installer. Your script can use npm or pip inside, but w3bs only ever runs your installer. That rule is why every one of our tools got a curl installer this week.

Signed when you want it

Publishers who want more than a script can run a signed repository with w3bs-publish. Those packages get TUF-signed metadata, checked downloads, pins, rollback and crash-safe updates. The format is an open spec, OpenPkg, and w3bs is its reference implementation.

More than packages

The same CLI resolves and verifies signed w3bs:// resources (w3bs resolve, w3bs verify), and more W3BS apps will land in it as new commands.

Linux and macOS, x86_64 and arm64. No Node, Python or Rust needed. Source: github.com/profullstack/w3bs.org.

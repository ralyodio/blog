I write in a terminal and I read in a terminal, and then I would open five browser tabs to post the same sentence five times. So I built myna. It is a social media manager that runs where I already am.

curl -fsSL https://mynaposter.com/install.sh | sh

That is a single binary with the runtime compiled in, so there is no Bun, Node or npm to install first. Linux, macOS and Windows. If you would rather use a package manager, bun add -g @profullstack/myna does the same job.

One post, counted per network

The usual approach is to write once and truncate to the smallest limit, which wastes every network that is not Twitter. myna counts the way each network counts. The same 140 character post with a link in it reads 139 on Mastodon and 140 on X, because X bills every URL at 23 characters regardless of how long the URL actually is. Past the limit it becomes a thread where threads exist, and gets split sensibly where they do not.

myna                                  # the TUI
myna login bluesky
myna post all "the release notes are up"
echo "shipping today" | myna post bluesky,mastodon
myna schedule "tomorrow 9am" "good morning" --to mastodon
myna accounts --json | jq '.[].id'

Every slash command in the TUI is also a subcommand, so anything I can do by hand can go in a script or a cron job.

The part everyone is vague about

Logging in. Most tools in this space say "connect your accounts" and let you discover the truth one network at a time. The 26 networks split four ways, and the site says so on the front page:

  • Six take a real username and password. Bluesky, Reddit, Lemmy, Matrix, Mattermost, WordPress. Use an app password where one is offered.
  • Nine want a token you paste. Telegram, Discord, Slack, Misskey, Nostr, dev.to, Hashnode, Ghost, Micro.blog.
  • One prints a code you approve in a browser. tsbb, via a device flow, so no password crosses the terminal and no local port has to be free.
  • The rest need a browser sign in, for two opposite reasons. Mastodon and its relatives let any client register itself, so you type the instance and click Authorize with no developer account anywhere. X, Meta, LinkedIn, Pinterest and TikTok removed their password APIs years ago and make you register an app first.

Two things that will bite you no matter what tool you use. Facebook and Instagram cannot post to a personal profile at all, so you need a Page you administer and a Business or Creator account linked to it. And Mastodon no longer accepts a password: grant_type=password is gone, and a current server answers unsupported_grant_type. myna used to offer the field and produce a confusing failure, so as of last week it does not.

Infographics with the right words on them

There is an optional writer, off unless you configure Anthropic, OpenAI or a local Ollama model. It drafts from a link and never posts on its own. The bit I am happiest with is the infographic path: the model picks the copy, myna renders the graphic from it. Text on the image is exactly the text in the post.

That is not a stylistic preference. Ask an image model to draw a chart with labels and it rewrites the labels, inventing figures and misspelling names. Separating the two removes the failure instead of hoping against it. There is still an image backend if you want illustration, and it is the only one where the words can come out wrong.

Where the credentials live

In ~/.config/myna/vault.json, encrypted with AES-256-GCM, on your machine. There is no myna account and no server in the path. The only thing that leaves your computer is the post you asked to send.

It is 0.2.0, about 12,000 lines of TypeScript across 13 network adapters, built on hqtui. MIT, source at github.com/profullstack/mynaposter, site at mynaposter.com.

What each feature actually costs me in AI

2026-08-21, by Anthony “chovy” Ettinger.

How this was written: drafted with an AI assistant from my own notes, then edited by me.

back to my blog postings

I have five agents running most days, each one in its own git worktree, and until recently I had no idea which piece of work was expensive. The invoice arrives monthly as one number. That number tells you nothing about whether the mobile nav fix was worth it.

So moshcode grew a cost command. This is mine from this morning:

mosh ▸ /cost --all
  run       engine  model          cwd                                            in    out   cache   cost
  798a6b89  claude  claude-opus-5  ~/…/rssamplifier.com/…/write-failure-noise      1.0k  325k  172.8M  $103.52~
  579e3383  claude  claude-opus-5  ~/…/tipoffwatch.com/…/plays-drives-commentary   952   256k  135.4M  $81.92~
  4a73f706  claude  claude-opus-5  ~/…/tipoffwatch.com/…/mobile-nav-safe-area      332   75k   21.8M   $15.16~
  b2d180b5  claude  claude-opus-5  ~/blog                                          36    11k   1.4M    $1.60~
  cfce82de  claude  claude-opus-5  ~/…/tipoffwatch.com/…/broadcast-fallback        410   129k  38.6M   $26.29~

  total  $228.49~  2.8k in · 797k out · 370.0M cached
  ~ estimated from published rates; unmarked figures are the engine's own.

The cwd column is the whole trick

There is no instrumentation here. Every agent CLI already writes down what it used: Claude Code keeps a usage block per message in ~/.claude/projects/**/*.jsonl, Codex emits cumulative token counts into its rollout files, opencode stores a cost it computed itself in SQLite. The command just reads those files and normalises them.

What makes it a per-feature ledger instead of a per-day total is that I run one worktree per feature. The directory name is the feature name, so grouping runs by working directory groups them by what I was building. write-failure-noise cost $103.52. mobile-nav-safe-area cost $15.16. I did not have to tag anything.

Where the money actually goes

Look at the columns rather than the total. 797k output tokens at Opus 5's published $25 per million is about $20. The 2.8k of input is around a cent. That leaves roughly $208 of the $228 sitting in one column: cache.

Over 90 percent of the bill is the model re-reading context it has already seen. Not thinking, not writing code, just carrying the conversation forward. Which reframes the optimisation entirely. Shorter prompts save nothing. Fewer, tighter sessions save a lot, because a session that runs for four hours pays to re-read its own history on every single turn.

Why the tilde matters

Every figure above carries a ~. I am on a subscription, so none of this appeared on a card. The tilde means the number was worked out from published rates, and it answers a different question: what would these tokens have cost on the API. Runs from engines that price themselves print without the tilde, because that is a measurement rather than an arithmetic exercise. Keeping the two visually apart was the part I cared most about getting right. A confident wrong number is worse than an honest estimate that says so.

Models with no rate on file are not guessed at. Tokens are counted, the cost comes back blank, and the command tells you to price it yourself in ~/.moshcode/pricing.json. Codex records model names like gpt-5.6-sol that appear on no public price list, so inventing a rate for it would just be lying with more steps.

The part I did not enjoy

Drafting this post cost $1.60. Chasing down a write-failure log noise problem cost $103.52 and did not ship a feature. I would have guessed those were within an order of magnitude of each other. They are off by 65x, and I only know that because the number is now sitting in a column next to the directory name.

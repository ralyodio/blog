OpenSaaS: the way out of a subscription, written down beside the way in

2026-09-19, by Anthony “chovy” Ettinger.

How this was written: drafted with an AI assistant from my own notes, then edited by me.

back to my blog postings

Subscribing takes one click. Cancelling takes a support ticket, a phone call in office hours and a retention screen. Regulators have started to say the two must be as easy as each other, and nobody can check, because the way out is not written down anywhere a reader can fetch.

OpenSaaS is one file a subscription service serves at /.well-known/opensaas.json about how to deal with it: its plans, and the way in and the way out of each. Subscribe, cancel, pause, resume, change plan, stop the mail, export your data, delete the account. Every action is described twice in the same place: the page a person opens, and the endpoint an agent calls with an OpenAccess scope.

Why both

A person needs the page. An agent acting for a person needs the endpoint and the grant that authorises it. Today the page is hidden and the endpoint does not exist, so "cancel the subscriptions I do not use" is a thing a person can ask an agent and an agent cannot do. With the file, an agent holding a grant for billing:cancel calls cancel.api and gets back done, scheduled, pending with what the service still needs, or refused with a reason. A refused cancel is still a refused cancel. The difference is that it is in writing.

The measure

Each action carries steps, the number of things a person does from the page to done, and confirm, what the service demands before the action takes: none, click, email, password, chat, call or mail. A directory shows cancel.steps beside subscribe.steps, and flags a cancel that needs a chat, a call or a letter, because none of those is a step an agent can take and each is a step most people give up on. The service wrote both numbers itself. The file came from its own origin. That is the verification.

Two actions, on purpose

unsubscribe is about mail and cancel is about the plan. Services conflate them on purpose, so the spec keeps them apart. A mail unsubscribe that carries RFC 8058 one-click headers says so with list_unsubscribe: true, the same promise the mail itself makes.

The first service and the first directory

nichedb.dev serves its own file at nichedb.dev/.well-known/opensaas.json: four prepaid plans, and five actions that are all real today. Cancel is one click and one call, effective immediately. Export answers at once with one JSON document. Delete confirms by email. Pause, resume and change plan are absent because nothing there pauses or converts a prepaid term, and absence in this file means unstated, never assumed.

nichedb is also the first directory reading the file. Its saas collection lists each plan with a "Way in, way out" table: subscribe steps against cancel steps, what confirm demands, whether an agent can do it, when it takes effect, what the refund is.

Serving one

By hand, from the billing table the service already keeps. A plan table and a cancel endpoint are everything the file needs. A service that has a cancel page and no cancel endpoint serves the page today and adds the endpoint and scope when it has them, and the file gets better without the URL changing. The smallest valid file is a service with a name and one action with a page.

The spec is at logicsrc.com/docs/opensaas, CC BY 4.0.

tipoffwatch, genrewatch and rssamplifier all work the same way. Somebody else publishes the data, it is free to read, the initial pile is large, and it gets bigger every single day without me doing anything. Games get released. Shows air. People publish feeds. The site just has to keep up.

This morning I asked which other niches have that shape. The list was long: package registries, SEC filings, rocket launches, court dockets, earthquakes, recalls, papers, status pages, extension stores. So instead of building site number four by hand, I built the platform and pointed it at all of them. nichedb.dev went live tonight.

The model

A collection is a niche. A source is one adapter pointed at one upstream with a config and a cadence. Every row it produces is an item. A feed is a saved query over a collection, and a feed is the thing people follow. It has a page, an RSS and JSON Feed rendering, an API endpoint, and it delivers by push, email or a signed webhook.

There are 13 collections and 29 adapters as of tonight, all keyless. Steam lists, npm's changes feed, PyPI, crates.io, Go's module index, Hugging Face, GitHub releases, EDGAR's latest-filings feed, the Federal Register, MusicBrainz, Open Library, Scryfall, The Space Devs, Lichess broadcasts, USGS quakes, NWS warnings, GDACS, any Statuspage host, Firefox add-ons, the VS Code marketplace, the MCP registry, openFDA recalls, ClinicalTrials.gov, arXiv and Crossref. An adapter is one file. Writing one takes about the time it takes to read the upstream's docs.

Enrichment

The raw rows are thin. A Steam entry is a name, a price and a date. So after ingest each item runs through the enrichers that apply to it: the top YouTube videos (the trailer, in practice), the Wikipedia paragraph, the repo's stars and licence, last week's npm downloads, the company behind a filing with its ticker and industry, a paper's TL;DR from Semantic Scholar. The results sit on the item under the enricher's name, and a feed picks which ones it shows. Defaults are on. A game feed carries trailers unless you tell it not to.

Two things I got wrong on the first pass and fixed before dinner. Newest first meant one arXiv sweep of 200 papers starved every other collection, so the worker now takes a fair share per collection each tick. And the top YouTube hit for an obscure game was a musical, so a video now has to mention the title to count.

For people and for agents

Every collection, source, feed and item is JSON under /api/v1. There is a stateless MCP server at nichedb.dev/mcp with 15 tools, and the CLI (npm i -g @profullstack/nichedb) doubles as a stdio bridge for Claude Code and friends. llms.txt describes the whole deployment in one document. Search engines and retrieval crawlers are welcome; training crawlers buy a day pass over x402, same as my other sites now.

It is open source, MIT, at github.com/profullstack/niche-db. One Postgres, one Redis, Bun and Hono. Run your own on the niche you care about and send me the adapter.

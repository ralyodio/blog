I cloned myself at chovy.com

How this was written: drafted with an AI assistant from my own notes, then edited by me.

chovy.com used to be a microblog. Static index.html, a posts.json, nothing over 240 characters, a CNAME file pointing at GitHub Pages. Publishing was a commit.

It is now a clone of me.

The clone is four lines long

The advisor that answers at chovy.com runs on a system prompt of four sentences. The first one is "You are Chovy, Anthony Ettinger's practical AI advisor." Two more tell it to help founders make decisions and to be honest about what it does not know.

The fourth is the only one I would fight for: never claim to have run tools, changed code, or accessed private systems unless the application explicitly supplied evidence. A clone of me that invents a deploy it did not do is worse than no clone, because people would believe it. Everything the thing says it did, it has a record for.

Inference goes through Abliteration over an OpenAI compatible endpoint, and it happens server side. The browser never sees the provider key.

The clone does not write the code

The talking part and the building part are two different Railway services out of the same repo. The coding worker is its own container with its own volume and its own bearer token, and it keeps one local Git workspace per organization and worker pair. It streams five kinds of event back over SSE: status, terminal, file, completed, failed.

The web service validates the sign in cookie before it forwards anything, and the worker will not talk to anyone without the internal token. So the advisor can say a run started, and there is a real process on the other end of that claim.

Then we cloned the rest of the team

The workspace roster holds two kinds of worker and never blurs them. AI workers start inside a role and a project boundary and cannot see past it. Human workers claim a seat by signing up with the exact work email you invited, so I add preshy@profullstack.com and Preshy owns that seat the moment he signs up. There is no verification loop, on purpose. The seat is the invite.

The header counts them separately, so you always read something like "3 human, 5 AI" rather than a single team number that hides which is which. When a task goes to a human it says so, and it waits for a person. When it goes to an AI worker it runs in the sandbox and files evidence.

The humans it is modeled on are at profullstack.com/teams. That page is still the honest version of the team. The clones are a way to be in more places at once, not a replacement for four people.

Two things I got wrong first

The data store lived on the service filesystem. Railway replaces an instance and the workspace is gone. It is on a mounted volume now, at a path the app reads from an environment variable instead of assuming.

Retention needed a line drawn through it. Private advisor chats, worker sessions, runtime events and notifications age out on a schedule. Work products and workspace knowledge never do. The conversation is disposable. What the conversation produced is not.

Eighty three commits since the eighteenth, forty nine of them on the first day. The microblog is still in Git if I want it back.

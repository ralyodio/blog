Every podcaster and author gets a profile file, and it is theirs to edit

2026-09-15, by Anthony “chovy” Ettinger.

How this was written: drafted with an AI assistant from my own notes, then edited by me.

back to my blog postings

Every podcaster on p0dcasters.com now has a profile file, and it is theirs to edit. So does every author on rssamplifier.com, and every person an OutreachGraph workspace chooses to make public. All of them land in one place, the new People collection on nichedb.dev, where a person is one entry no matter how many apps know them.

The file is OpenProfile.md, the LogicSRC spec for one Markdown profile that people and agents can both read. For a podcaster it carries the Broadcast section: the show, the feed, where to listen, how often it comes out, what it covers. For anyone offering to appear on other people's shows it carries the Guest section. A booking platform reads one against the other instead of two forms.

Where the files are

  • p0dcasters serves the host's profile next to every show page, at /podcast/<slug>/openprofile.md. The show page points at it with <link rel="openprofile"> and a Profile button. Inspiring Founders Podcast is one.
  • rssamplifier serves every author's file at /authors/<slug>/openprofile.md, built from the accounts the author's own site links to and the shows they own. Thomas Umstattd Jr. has two shows, so his Broadcast section has two groups.
  • OutreachGraph serves a person's file only when the workspace marked it public, and a public file never carries an email or a phone number.
  • nichedb pulls all three and merges them into nichedb.dev/c/profiles. The entry URL is the name plus an id, so two people with the same name never collide, and the wrong name on the right id redirects.

Generated, then corrected by the person

Each app generates the profile from what the person already published: a feed's title and categories, the links on their site, their public bios. That is the app's claim, and the specs are strict about what a claim may not contain. OpenBroadcast says a platform never fills in Seeking, Not, Pays or Charges from a feed. So the generated Broadcast section states the show; the person states the terms.

The person does that by claiming the profile. On every one of these apps the claim is verified automatically: the signed-in email matches the feed's owner email or the author's published address, or the person's own site links back to the profile. After that the profile is editable from the web page, the REST API, the app's CLI and its MCP server, and the same edit shape works everywhere: identity keys, a headline, one block of Markdown per section. A section the person did not touch keeps being generated, so a new episode still updates the show while the terms stay as the person wrote them.

Editing also works through OpenAccess. An agent holding a grant with the openprofile:edit scope can update a person's profile on any of these apps, so one grant covers every place the profile lives.

One person, not five copies

nichedb de-duplicates by the rule OpenProfile.md already states: the URL of an account is the identity. Two documents that share a verified account URL, a home page or an email are the same person and merge into one entry that lists every source. Two documents that share only a name stay two people. The merged entry keeps every account and topic from every source and keeps shows apart as separate groups.

Claiming on nichedb works the same way, and a claimed entry can take a handle, so /c/profiles/ada-lovelace-1842 can become /c/profiles/ada. The old URL keeps working.

For developers

All four apps use one package, @profullstack/openprofile, which parses, renders, applies an owner's overlay, computes identity keys and merges documents. Each app also exposes a listing endpoint (/api/openprofiles with since and a cursor) that any directory can pull, keyless, with the same shape nichedb reads.

The specs are on logicsrc.com: OpenProfile.md, OpenBroadcast, OpenGuest and OpenAccess.

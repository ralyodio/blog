Post once, everywhere: myna now writes to your blogs and runs an ad for each post

myna is the terminal social media manager we build at Profullstack. Until today it posted to 27 networks and stopped there. A launch still meant writing the announcement, pasting it into the blog by hand, and then remembering to buy an ad for it, which nobody remembered to do. Version 0.6.0 closes that loop.

Two new networks: your own blogs

Most of our blogs are not a CMS. hqtui.com keeps one Markdown file per post in a repository and deploys on merge. This blog is a directory of plain HTML pages where writing the file is publishing. myna now treats both as networks.

  • Git blog commits a Markdown file with frontmatter through the GitHub API. No checkout, no clone, and the site's own deploy publishes it. The token is optional: it uses gh auth token when you have one.
  • HTML blog writes the next numbered page, lists it in the index, rebuilds the feed and pushes a mirror repository if you keep one. When the blog-post tool from cli-tools is installed the page is written by it, byline and all.

Neither is ever part of myna post all. A social post fanned out by accident is an embarrassment. A blog page fanned out by accident is a publication and a commit, so a blog only posts when you name it:

myna post --to htmlblog --description "One line for the feed" < post.md

An ad for every post

The bundled CrawlProof plugin listens for posts. When a post lands on a blog, the page's URL goes to crawlproof.com, which reads the page, writes the creatives from it and starts a campaign on the ad network that runs across our sites. Nothing to configure beyond myna crawlproof login and an API token. Social posts do not get a campaign of their own, since the post is the promotion, but --ad true runs one for the first URL in any post.

CrawlProof got the matching half today: campaigns and publisher slots can now be created with an API token, from its own CLI or from any program, and its stats know when a visit came from an ad, so a post's page shows how many readers the campaign sent.

Why

We noticed that most of what we shipped this year never got announced anywhere, and that when it did, the announcement and the ad were two separate chores done by two separate people. Now they are one command, and the command is part of the release.

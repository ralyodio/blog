Claude Code, OpenCode and Codex are good at code and bad at everything that lives in a GUI. The usual fix is a browser sandbox or a pile of cloud connectors. We wanted something else: the agent drives the desktop you already use, with a real mouse and keyboard, and you hold the switch.

That is the Agentic Desktop Layer, a W3BS project. Version 0.2 installs with one line on Linux, macOS and Windows. Docs at w3bs.org/desktop, code in the w3bs.org repo, Apache-2.0.

# macOS and Linux
curl -fsSL https://w3bs.org/desktop/install.sh | sh

# Windows (PowerShell)
irm https://w3bs.org/desktop/install.ps1 | iex

How it behaves

  • It starts Disabled after install, login, restart or a crash. Only you turn it on, from the tray (KDE, Windows), the GNOME panel or the macOS menu bar. Agents cannot enable it or approve their own requests.
  • Disable stops everything at once and releases any keys the layer was holding. So does the emergency shortcut: Super+Alt+Escape on Linux, Win+Alt+Esc on Windows, Control+Option+Command+Escape on macOS. Locking the screen does too.
  • Permission is checked before every single input event. One agent controls the mouse and keyboard at a time.
  • Every click names its target. A click on a window something else now covers, or typing after focus moved, is refused instead of guessed.
  • The audit log keeps metadata only. Never screenshots, never typed text.

Agents connect through a local stdio MCP server: w3bs-desktop setup claude-code prints the line to add it.

How it was tested

Not on our laptops. The KDE Plasma and GNOME backends run in disposable containers with real headless sessions: 52 checks on KDE, 72 on GNOME. Windows and macOS run on GitHub's hosted desktops: 54 checks on Windows, 22 on macOS, plus both installers end to end. The checks type real text (including é, € and emoji), move the pointer and read its position back, click, take screenshots, and pull the plug mid-typing.

What is not done

No platform is certified yet. Multiple monitors, the lock screen and password prompts on Windows and macOS, and a real logout and login have not been proven on the test machines. Builds are not code-signed, so macOS may ask for permissions again after an upgrade. On GNOME, text with characters your keyboard layout lacks is refused rather than typed partially.

A note on Vela

We were told the Vela desktop had every hook we needed. We checked it clean room: one agent read the GPL code and wrote down only the interfaces, the implementer never opened the source. Vela's window, lock and password-prompt hooks are good and the layer uses them. Mouse and keyboard injection only exists behind a debug switch, so the safety model lives in the layer.

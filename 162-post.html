c0upons.com launched as a community coupon site and then sat empty. Nobody types a promo code into a page with nothing on it, so the community never formed. That is the chicken and egg every user generated site starts with, and the way out is to seed it. As of today it seeds itself from nichedb.dev.

Where coupon data actually comes from

We started by asking where a site like Capital One Shopping gets its catalogue. The answer is nowhere you can plug into. Their codes are crowdsourced from users' checkouts by the browser extension, tested automatically, and monetised through the affiliate networks: Rakuten, CJ, Impact, ShareASale, Pepperjam and Awin. Every one of their hosts refuses requests from a datacenter before it even looks at auth. And every affiliate network's coupon API wants an approved publisher account first.

What does answer, with no key and no contract, are the feeds the deal communities and deal desks publish themselves. So that is what the new collection reads.

The deals collection

nichedb 0.10.0 adds deals, with five adapters and nine sources:

  • Slickdeals: the front page, the popular list and a search for coupon codes. Every post names its store and the destination host on the outbound link.
  • DealNews: latest and hottest, with the retailer, price, expiry, category, deal type and staff pick published as fields rather than prose.
  • Dealcatcher: fifty deals a day, store read from the title.
  • Ben's Bargains: twenty at a time, and the house style names the code, the discount and the price in every post.
  • r/deals and r/coupons: as posts, with any code lifted from the body.

One shared extractor reads the code, the discount and the price out of the text and writes the same store fields on every row. So a consumer joins on one store key across all five sources, and a coupon-code tag marks the rows a shopper can actually type at checkout. Four feeds ship on day one: coupon codes, editors' picks, Amazon deals, and everything.

The first tick pulled 267 deals and 42 codes. It runs every half hour.

How c0upons uses it

c0upons 1.3.0 reads the collection in id order, keeps a cursor, and upserts stores and coupons. A deal that names a store becomes a row, code or not, because a store page with prices on it is what a shopper came for. A Reddit post is taken only when it carries a code. The sync route is keyless and throttles itself to one run every ten minutes, and the same schedule that keeps the database awake now calls it every fifteen. Nothing had to be run by hand: the sync creates the columns it needs on first run.

The made up sample codes the migration used to seed an empty database are gone. What is on the site now is what the deal desks published today.

Read it yourself

The collection is at https://nichedb.dev/c/deals and the API is GET https://nichedb.dev/api/v1/items?collection=deals. The coupon site is https://c0upons.com. Both are open source: github.com/profullstack/niche-db and github.com/profullstack/c0upons.

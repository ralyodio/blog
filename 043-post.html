If all your traffic is bots, sell to the bots

The last post was the discovery: 80,000 pageviews a day on genrewatch, 99% of them Meta's training crawler, 27 real people. rssamplifier was 87% bots. The reflex is to ban them. I want to argue the other way.

A bot is a customer with a budget

A training crawler is not a freeloader who wandered in. It is a program somebody runs on purpose, with a budget, to collect exactly what you publish. It wants the pages. It reads robots.txt. It parses status codes. It is the most literal-minded buyer you will ever have, and it never argues about price.

Blocking it earns nothing, and it protects nothing either, because a training crawl never sends a reader back. Charging it is pure margin. The pages already exist, the server is already up, and the bot was going to fetch them anyway.

How you advertise to a robot

You cannot run a banner at GPTBot. What you can do is put the offer where a program will find it.

  • robots.txt names the paid agents and points at a sales page. Every crawler reads it first.
  • Every gated page answers 402 Payment Required with a machine-readable x402 offer in the body: price, currency, chains, where to pay. The status code is the ad.
  • /crawl answers every user agent, HTML for a person and JSON for a program, so the operator who looks into why the crawl stalled sees the price and a one-line command to pay it.

Then keep it cheap enough that paying is easier than working around it. One dollar a day, seven for a week. The pass is a signed token in a header. No account, no signup, no email.

The gateway does all of that

@profullstack/x402-gateway is the package. Zero dependencies, one middleware, no database. With Hono:

import { createGateway } from '@profullstack/x402-gateway';
import { x402Gateway } from '@profullstack/x402-gateway/hono';

const gateway = createGateway({
  siteUrl: 'https://your-site.com',
  coinpay: { apiKey: process.env.COINPAY_X402_KEY },
  payTo: process.env.CRAWL_PAY_TO,
});

app.use('*', x402Gateway(gateway));
app.get('/robots.txt', (c) => c.text(gateway.robotsTxt()));

Next.js is the same three calls in proxy.ts. Anything else hands gateway.handle(request) a Fetch Request and sends back whatever it returns. The package carries the agent lists (training on one side, retrieval on the other), the robots.txt generator, the sales page, the pass signing, and the CoinPay verify and settle calls. Retrieval crawlers, the ones behind AI answers that cite you, stay free. So do people, Google and Bing.

Between this morning and tonight it went onto 38 sites. For a Next app the wiring is one file and a matcher.

Somebody paid

At 21:43 UTC tonight the first real dollar cleared: one USDC on Base, from our own crawler wallet to rssamplifier.com, through the matching client, @profullstack/x402-client. The gateway verified the proof, CoinPay's relayer broadcast the transfer, the pass opened the site, and the payout wallet went from 20 to 21. Paying ourselves is not revenue, but the plumbing is proven end to end, which the last post could not say.

The client matters as much as the gate. Our own crawlers on rssamplifier, brisk, b1dz, crawlproof and meshhook now pay a 402 when they meet one, capped at five dollars a wallet. If we want bots to pay, our bots pay.

Both packages are JavaScript today: Node, Bun, Deno and the edge. MIT, on GitHub under profullstack.
